# macbench —— Mac 电池状态性能对比跑分工具

一个**零依赖**的 shell 脚本(只需 macOS 自带的 clang 和系统命令),用于对比
**电池正常**和**电池故障/缺失**两种状态下 Mac 的真实性能差异。

兼容 Intel 和 Apple Silicon (M1/M2/M3) 的 Mac。

---

## 为什么电池坏了会影响性能?

Mac 的电源管理系统把电池当作供电系统的一部分。当电池故障、被识别为失效或
缺失时,即使插着充电器,macOS 也可能认为供电能力不足,从而:

1. **主动降频**:`CPU_Speed_Limit` 被压到 50%(甚至更低),CPU 只允许跑一半速度;
2. **禁用睿频 (Turbo Boost)**:多核满载时无法短暂冲到睿频频率;
3. 部分机型还会限制 GPU 性能。

这些状态可以用系统命令直接观测到:

- `pmset -g therm` → 看 `CPU_Speed_Limit`(100 = 不限速,50 = 限速一半)
- `sudo powermetrics` → 看 CPU 实际运行频率

本脚本把**限速状态**和**实际计算性能**放在同一次运行里记录,这样对比结果
既有"跑分证据",也有"系统自我报告的证据",结论经得起验证。

## 快速开始

```bash
# 第一次运行前,给脚本加执行权限
chmod +x macbench.sh

# 正常跑分(约 30 秒,含中文交互引导)
./macbench.sh
```

运行中脚本会:

1. 显示机型、芯片、核心数、内存信息;
2. 检查当前是"电池供电"还是"接通电源",如果用电池供电会警告并询问是否继续;
3. 读取电池健康信息(循环次数、容量、是否报告永久故障);
4. 读取系统限速状态,若 `CPU_Speed_Limit < 100` 会醒目提示;
5. 请你给这次测试起个名字(如"坏电池接电源");
6. 依次跑三项测试:单核 → 多核 → 内存带宽;
7. 结果保存到 `results/result_时间戳.txt`。

## 对比两次测试

在**两种状态下各跑一次**(中间不改变其他条件),然后:

```bash
./macbench.sh compare results/result_旧.txt results/result_新.txt
```

输出示例(假想):

```
项目             第一次        第二次    比值(二/一)
单核分数          210.0        105.0        0.50
多核分数          830.0        410.0        0.49
内存带宽          30.20 GB/s   29.80 GB/s   0.99
```

### 如何判读结果

| 现象 | 结论 |
|------|------|
| 单核/多核比值 ≈ 0.50 | 性能被限制了一半,典型的无电池降频 |
| 多核比值明显低于单核比值 | 睿频被禁用,或部分核心被限制 |
| `CPU_SPEED_LIMIT < 100` | 系统在主动限速,直接证据 |
| 内存带宽比值 ≈ 1.0 | 内存未被限制(正常现象,降频主要影响 CPU) |
| 所有比值 ≈ 1.0 且无限速 | 两种状态性能无差别 |

## 完整操作流程(你的场景)

### 场景 A:2017 款 Intel 13 寸 MacBook Pro(电池故障)

1. 插好充电器,关掉浏览器、聊天软件等一切可关的程序;
2. 运行 `./macbench.sh`,测试名填"坏电池接电源";
3. (可选)运行 `./macbench.sh --freq` 额外读取实际 CPU 频率,
   输入开机密码。i5-7360U 标称 2.3GHz / 睿频 3.6GHz,
   如果实测只有 1.2GHz 左右,即确认降频;
4. 之后如果换了电池,在同样条件下(插电源、无其他负载)再跑一次,命名"换新电池后";
5. 用 `compare` 对比两次结果。

### 场景 B:M1 笔记本

用法完全相同。注意两点:

- Apple Silicon 的 M 系列芯片不提供 `hw.cpufrequency_max` 系统值,
  脚本会显示"(Apple Silicon 不提供此值)",这是正常现象,不影响跑分;
- M 系列芯片在电池供电和接电源时性能差异通常比 Intel 小,
  但电池故障时同样可能触发限速,对比方法一致。

### 建议:同一状态跑两次,验证分数稳定性

正式对比之前,建议先在**同一状态下**连跑两次并 compare 一次。
如果比值在 0.95 ~ 1.05 之间,说明测试环境稳定,之后的对比才可信;
如果两次都飘得很厉害,说明有后台干扰,先解决再测。

## 所有选项

| 命令 | 作用 | 耗时 |
|------|------|------|
| `./macbench.sh` | 正常跑分,含中文交互 | 约 30 秒 |
| `./macbench.sh --auto` | 跳过交互(电池供电时不再询问) | 约 30 秒 |
| `./macbench.sh --quick` | 快速验证脚本可用,**分数不能用于对比** | 约 8 秒 |
| `./macbench.sh --freq` | 额外用 sudo 读 CPU 实际频率 | 约 40 秒 |
| `./macbench.sh compare 旧 新` | 对比两次结果 | 瞬间 |

选项可以组合,例如 `./macbench.sh --auto --freq`。

## 测试原理(供技术验证)

- **测试程序**:运行时用系统 clang 临时编译一个小 C 程序(`cc -O2`),
  三项测试分别是:
  - **单核**:1 个线程,固定 1 秒预算内循环执行"双浮点递推 + 整数位运算
    混合负载",统计完成的总迭代数。结果参与返回值,防止编译器把循环优化掉;
  - **多核**:同上,但线程数 = CPU 核心数;
  - **内存**:256 MB 缓冲区反复 `memcpy`,统计总带宽 GB/s
    (每轮修改源缓冲并读取目标缓冲,防止被优化掉)。
- **计时**:用 `CLOCK_MONOTONIC_RAW` 单调时钟,不受系统时间调整影响;
- **分数定义**:单核/多核分数 = 每秒完成迭代数 ÷ 10⁸ × 100,
  同一台机器上直接对比即可,跨机器对比分数没有意义;
- **误差来源**:后台程序、散热状态、电源模式。对比前请保持两次测试条件一致。

所有中间数据(限速状态、电池信息、原始迭代数)都写进结果文件,
任何人都可以用相同脚本复现验证。

## 安全性说明

- 脚本**不需要安装任何软件**,只用 macOS 自带的 `cc`、`pmset`、`ioreg`、
  `sysctl`、`awk` 等系统工具;
- 唯一需要密码的地方是可选的 `--freq` 模式,用 `sudo` 运行
  `powermetrics`(只读的系统性能采样工具,macOS 官方自带);
- 脚本不访问网络、不修改任何系统设置、只写入两个位置:
  脚本目录下的 `results/` 和系统临时目录(自动清理);
- 测试程序源码以明文嵌在脚本里,可自行审阅;
- 对比模式对输入数值做了合法性过滤,只接受纯数字。

## 常见问题

**Q: M1 上 `标称最高频率` 显示为空?**
A: Apple Silicon 不提供该系统值,正常现象。可用 `--freq` 看实际频率。

**Q: 为什么不用 Geekbench?**
A: Geekbench 结果更全面,但需要下载安装、分数受版本影响、不易脚本化对比。
本脚本针对"电池状态对比"定制:把限速状态和跑分绑定记录,直接输出比值。

**Q: 跑分和对比是同一台机器才有效吗?**
A: 是。分数只用于**同一台机器前后对比**,跨机器比较没有意义。

**Q: 测试时必须插着电源吗?**
A: 对比"坏电池接电源"和"换电池后接电源"时,两次都插电源,保持一致即可。
如果单独想测"电池供电性能",脚本也会记录供电状态,但注意苹果对电池供电
本身也可能有性能管理策略。
